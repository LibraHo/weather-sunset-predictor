# 需求文档

## 文档定位

本文件只保留当前产品需求和验收口径。历史 PR 记录、阶段流水、已废弃方案不再写入本文，回溯时使用 git history、PR、`docs/` 和真实案例库。

## 产品目标

霞客提供朝霞/晚霞预测、地图趋势、照片分享和多端体验，核心目标是：

- 给用户一个可信的 0-100 观赏评分和明确解释。
- 区分单点精细预测与区域地图趋势，避免地图分数被误读为精细点位预报。
- 支持 Web、小程序和开放 API 的一致核心能力。
- 用真实反馈案例持续校准算法，不写城市/日期特殊规则。

## 当前产品范围

### 单点朝霞/晚霞预测

- 用户输入地点、日期、时段后，系统返回评分、质量等级、最佳观赏时间、日出/日落方向、天气与算法解释。
- 点位天气主来源为 Open-Meteo；必要时可有受控 fallback，但响应必须标注来源和降级原因。
- 主链路必须使用闭环后端计算：本地点天气 + 日出/日落方向云量采样 + 统一评分算法。
- 朝霞按日出方向评估，晚霞按日落方向评估，方向使用当天当地太阳方位角，不用固定正东/正西。

### 三日预测

- 首页和小程序展示未来三天的朝霞/晚霞卡片。
- 批量接口应复用同一地点天气数据，避免重复请求扩大 Open-Meteo 压力。
- 三日预测应与单点主链路使用同一评分函数和同一方向采样口径。

### 火烧云地图

- 地图展示区域趋势，不承诺精细点位分数。
- 当前公开地图优先使用 GFS 天气网格 + CAMS 气溶胶网格，Open-Meteo 网格仅作 legacy/fallback。
- 地图评分必须重跑项目自己的地图简化算法，禁止直接使用上游或中间产品自带的 `score/firecloudScore` 作为最终分。
- 地图方向逻辑按日出/日落方位查邻格，用本地格判断画布与遮挡，用方向邻格判断区域趋势。

### 解释与文档

- Web 算法页、小程序算法页、预测分析弹窗和评分细则必须保持同一口径。
- 用户可见新增文案必须走 i18n；大段新文案至少补 zh-CN、zh-TW、en-US。
- 算法变化必须更新真实案例回放或新增测试，不能只改视觉文案。

### 分享、账号与后台

- 微信/Google 登录用于个人能力、照片投稿和后续会员能力。
- 分享页、OG 图和照片地图必须保护隐私，默认只展示用户主动公开的数据。
- 管理后台提供用户、照片、访问统计、数据管线和健康状态视图。

### 开放 API / Agent API

- API Token 支持创建、禁用、删除、配额、最近使用时间和审计日志。
- Agent 预测接口应尽量复用主预测闭环逻辑，避免与 Web/小程序主链路产生评分漂移。
- API 错误必须结构化返回，包含 code、message 和必要的 degradedReason。

## 数据与隐私

- 地点、天气、照片、账号和访问日志按最小化原则存储。
- 未登录用户可以使用核心预测；登录能力不能阻断基础查询。
- 照片 EXIF 位置、用户身份和审核状态不得泄露给未授权用户。

## 核心验收

- 主预测接口返回 Open-Meteo 来源、方向采样信息和算法版本。
- 地图接口返回 `mode/source/degraded/degradedReason/updatedAt`，可区分 GFS/CAMS 与 fallback。
- 真实案例库回放通过，至少覆盖灰幕低分、暖色散射高分、雨季高云、方向云幕等典型场景。
- Web、小程序、API 三端对同一主链路分数没有无解释的大幅偏差。
- PR 合并前相关测试通过；部署后验证 `/health`、首页、主预测、地图和变更功能。

## 当前高优先级需求

### R1 地图 raw score 泄漏修复

- 地图产品点可保留原始字段用于调试，但最终公开 `score` 必须来自 `calculateMapSimplifiedPrediction()`。
- 缺少必需 GFS 字段时不得回退到原始 `score/firecloudScore`。
- 验收：生产地图不再出现由产品原始分导致的整体 90+ 暴涨。

### R2 朝霞 v2 对齐

- 朝霞目前共享底层云/光路/渲染模型，但 sunset 专用 `scoringV2` 未完全镜像。
- 需要明确朝霞是否使用同等 v2 载体、光路、空气显色模型；若启用，应补朝霞真实案例和回归测试。

### R3 入口一致性

- `/api/prediction/home`、`/api/prediction/enhanced`、batch、小程序首页应为主链路。
- 旧 GET、share、agent forecast/explain 等兼容入口需要标注 fast/legacy 或接入方向采样，避免分数漂移。

### R4 地图区域时间口径

- 地图产品选择当前以北京参考点决定下一次朝霞/晚霞时间。
- 对中国、日本、韩国大范围地图，需要评估是否按区域/格点本地事件时间选产品，避免东西向时差影响。

- 完成后只保留当前仍有价值的需求，历史完成记录移动到 PR、changelog 或 git history。
