## 1) 逻辑实现检查

### 已实现且合理
1. **应用启动态恢复与 API 配置初始化完整。**
   - `sessionToken/currentUser/latestPrediction/recentQueries/favorites` 会从 storage 恢复并回写到 `globalData`，随后调用 `configureApi` 注入 token。  
2. **首页查询链路闭环完整。**
   - 输入地点或使用定位 → 地理编码 `searchLocations` → 预测服务 `getEnhancedPrediction`（或注入服务）→ 归一化数据 → 缓存最新结果 → 跳转结果页。  
3. **多服务注入兼容策略稳健。**
   - `callPredictionService` 支持对象方法名探测（`predict/query/getPrediction/...`）和函数式服务，便于测试与未来替换。
4. **离线降级体验可用。**
   - 最近查询优先读取本地，远程读取失败静默，不阻塞主流程。

### 发现的问题/风险
1. **首页“收藏地点”点击复查存在潜在不完整查询。**
   - `useHistory` 对收藏项仅使用 `data-location` 设置 `locationText`，若收藏对象未携带坐标，会走二次 geocoding；若地名歧义，可能与用户期望不一致。建议在收藏项 data 中同步绑定坐标，优先直查。  
2. **日期传参使用 `toISOString()`（UTC）存在跨时区日期边界风险。**
   - `resolvePredictionDate` 在本地“明日”场景下返回 UTC 字符串，后端若按本地日切逻辑处理，可能出现日期偏移。建议改为显式本地日期（如 `YYYY-MM-DD` + 时区）或与后端统一约定。

## 2) 功能完备检查

### 当前已覆盖
- 首页：地点输入、定位、朝霞/晚霞切换、今日/明日切换、错误提示、最近查询展示。
- 结果页：分数、等级、最佳时间窗、指标展示（由预测归一化层提供）。
- 图库页：列表加载、空态/错误态、链接分享。
- 投稿页：图片选择、元数据字段、上传流程。
- 服务层：鉴权、地理编码、预测、用户收藏/最近查询、图片相关 API。

### 待补强（建议）
1. **收藏闭环缺失 UI。**
   - 目前首页展示 `favorites`，但未见“加入收藏/取消收藏/管理排序”入口，建议补齐。
2. **查询历史与收藏的去重主键策略可更稳。**
   - 目前近期查询主要按 `locationName` 去重，建议增加 `lat/lon + period + day` 复合键策略，避免同名地点冲突。
3. **状态可视反馈可再细分。**
   - 例如 geocoding 中、预测中分别给出阶段文案，有助于弱网场景理解。

## 3) 设计语言检查

### 优点
- 全局设计 token 注释明确，utility class 完整。
- 深色夜空背景 + 暖色强调 + 玻璃卡片风格在首页、图库、投稿等页面一致。
- 主要按钮、输入框、状态卡片都已映射到统一语义类。

### 建议
1. **语义化 class 可再收敛。**
   - 当前存在 `xiake-*` 与历史类名并存，建议逐步迁移并保留映射层，减少新页面心智负担。
2. **文字层级可增设“最小可读字号规范”。**
   - 部分 `25rpx` 文本在低端设备上可能偏小，建议定义最小正文字号并统一。

## 4) 设备适配检查

### 现状判断
- 采用 `rpx`、`flex`、`grid`，对主流机型适配基础较好。
- 列表和卡片布局在常规宽度下结构清晰。

### 适配风险点
1. **首页双列信息卡在窄屏可能拥挤。**
   - `placeholder-grid` 固定两列，建议在极窄宽度下退化为单列。
2. **触达面积与无障碍。**
   - 建议确保关键点击项最小触达面积（接近 44px 规则），并为图标/按钮补充可访问性文本（若尚未覆盖）。
3. **刘海屏/底部安全区。**
   - 建议补充 `safe-area-inset-bottom` 相关内边距策略，避免底部按钮在部分设备贴边。
