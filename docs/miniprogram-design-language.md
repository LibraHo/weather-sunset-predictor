# 霞客小程序设计语言规范

本文档定义霞客微信小程序的可执行设计语言。目标是让小程序、未来 iOS 与现有 Web 保持同一产品气质，但不复用 HTML/CSS/DOM 实现；平台代码只复用 token 语义、信息优先级和文案口径。

## 1. 产品气质

- **工具优先**：用户打开后先看分数、地点、时间窗口和关键天气指标，装饰只服务扫读。
- **深色天空底色**：默认以夜空深蓝/近黑作为背景，突出晚霞、朝霞和照片内容。
- **日光金 / 暖橙强调**：高分、主要行动、最佳窗口使用暖色；不要把所有信息都染成橙色。
- **玻璃层级**：卡片可使用半透明深色、细边框、轻阴影表达层级；避免大面积高模糊导致低端机卡顿。
- **普通用户语言**：写“今晚 18:40–19:15 更值得看”，不要写“算法窗口命中率提升”。

## 2. 颜色 token 语义

小程序 WXSS 与未来 iOS 都按语义 token 实现，不要求变量名完全一致。

| Token 语义 | 建议色值 | 用途 |
| --- | --- | --- |
| `bg.sky` | `#07111f` / `#0b1628` | 页面底色、导航栏背景 |
| `surface.glass` | `rgba(15, 28, 48, 0.78)` | 主卡片、结果容器 |
| `surface.raised` | `rgba(24, 42, 68, 0.86)` | 弹层、输入面板、上传区域 |
| `border.soft` | `rgba(255, 255, 255, 0.10)` | 卡片分割线、输入框边界 |
| `text.primary` | `#f7fbff` | 分数、标题、主文案 |
| `text.secondary` | `#b9c7d8` | 指标说明、辅助信息 |
| `text.muted` | `#7f8fa3` | 次要时间、占位、脚注 |
| `accent.sunGold` | `#ffd166` | 分数高光、最佳窗口、强推荐 |
| `accent.sunsetOrange` | `#ff8a3d` | 主按钮、关键入口、进度强调 |
| `accent.warmRed` | `#ff5d5d` | 错误、风险、上传失败 |
| `accent.clearBlue` | `#63b3ff` | 定位、地图、链接、可点击辅助动作 |
| `status.success` | `#57d68d` | 成功、已保存、上传完成 |
| `status.warning` | `#ffd166` | 弱网、权限待开启、低可信提示 |

使用规则：
- 主行动按钮优先用 `accent.sunsetOrange`，高分徽章用 `accent.sunGold`。
- 低分、失败、拒绝权限不要用高饱和暖橙，避免误导成推荐状态。
- 照片和地图上方的浮层必须保持足够对比度，文字对比至少满足移动端可读。

## 3. 层级与间距

- 页面横向安全边距：`16px`；窄屏最小不低于 `12px`。
- 卡片内边距：工具型信息卡 `12–16px`，表单/上传卡 `16px`。
- 组件间距：同组 `8px`，跨组 `16px`，页面大段落 `24px`。
- 圆角语义：
  - `4px`：小标签、指标 pill、状态角标。
  - `8px`：标准卡片、输入框、按钮；这是霞客小程序默认卡片圆角。
  - `12–16px`：大面板、底部弹层、照片预览容器。
  - 圆形：头像、定位点、地图 marker 数量角标。
- 阴影只用于浮层或照片上方控件；列表卡片优先用边框和背景层级。

## 4. 字号与排版

| 场景 | 建议字号 | 规则 |
| --- | --- | --- |
| 分数数字 | `48–64px` | 首页/结果页最高优先级，只保留 0–100 分。 |
| 页面标题 | `22–28px` | 首页问候、结果页地点名。 |
| 卡片标题 | `17–20px` | 预测模块、上传模块、地图模块。 |
| 正文 | `14–16px` | 普通说明、表单提示、错误说明。 |
| 指标数值 | `16–20px` | 云量、能见度、湿度、AOD 等。 |
| 辅助/脚注 | `12–13px` | 来源、更新时间、权限说明。 |

排版规则：
- 分数和最佳窗口永远优先于长解释。
- 一屏内不要同时出现多个同等重量的大标题。
- 长解释最多 2–3 行，详情可折叠或进入说明页。
- 中英文混排时保留数字和单位的可读空隙，例如 `18:40–19:15`、`AOD 0.18`。

## 5. 信息优先级

结果页从高到低：
1. 地点、朝霞/晚霞、日期。
2. 分数、等级、是否值得看。
3. 最佳观赏窗口。
4. 关键指标：高/中/低云、能见度、湿度、AOD/颗粒物。
5. 简短原因：为什么高分或低分。
6. 操作：收藏、分享、上传照片、查看地图。
7. 数据来源、更新时间、误差说明。

指标展示规则：
- 指标卡优先显示“数值 + 轻解释”，例如“高云 62%｜晚霞铺色条件较好”。
- 指标不够好时直接说明影响，例如“能见度偏低，霞光可能发灰”。
- 不向普通用户暴露内部权重、模型阈值或调试字段。

## 6. 组件规则

### 按钮

- 主按钮：暖橙背景、深色或白色文字，圆角 `8px`，高度 `44–48px`。
- 次按钮：玻璃背景 + 细边框，用于“手动搜索”“查看地图”“重新授权”。
- 危险按钮：仅用于删除投稿、清除数据，使用红色语义，不与主按钮并列争抢。
- 禁用态：降低透明度并给出原因，不只变灰。

### 卡片

- 标准卡片使用 `surface.glass`、`border.soft`、`8px` 圆角。
- 分数卡可以更大，但仍要保留工具密度；避免为了氛围牺牲首屏信息。
- 卡片标题、状态、主要数值必须可被单眼扫读。

### 输入与搜索

- 搜索框默认深色玻璃面，左侧地点/搜索图标，右侧清除按钮。
- 空输入提示写“输入城市或地点”，不要写接口字段名。
- 搜索结果列表优先展示地点名、行政区/国家和 provider 置信提示；不要展示调试 JSON。
- 定位失败时给手动搜索入口，不能卡死在授权流程。

### 状态与反馈

- Loading：使用轻量骨架或小型 spinner，并显示当前动作，如“正在计算今晚晚霞”。
- Empty：给可执行下一步，如“还没有收藏，先查一个地点”。
- Error：说明问题 + 恢复动作，如“网络不稳，稍后重试”。
- 权限拒绝：解释用途 + 提供“手动搜索 / 重新开启授权”。

### 照片

- 上传入口优先展示照片预览、地点、拍摄时间和公开展示说明。
- 缩略图优先于原图；列表、marker、预览卡默认用 `thumbUrl`。
- 上传前必须提示照片可能公开展示在分享地图。
- 无 EXIF 时不报错，允许手动补地点和拍摄时间。

### 地图

- 地图控件保持深色浮层，按钮不遮挡 marker 聚合和缩放控件。
- marker 优先显示代表缩略图 + 数量角标；无图时使用霞客图标或地点点位。
- 点击聚合展示小网格或列表，先显示地点、数量、最近拍摄时间。
- 经纬度、聚合半径、marker 渲染层不要写死微信组件私有字段，未来 iOS 要能复用数据结构。

## 7. 文案口径

- 推荐：`今晚 18:42–19:16 值得看`。
- 推荐：`高云条件不错，但能见度一般，颜色可能偏柔。`
- 避免：`云量阈值命中，scoreAerosolScattering 加权为正`。
- 避免：`请授权 scope.userLocation，否则接口不可用`。
- 权限说明要写用途：`允许定位后，可直接查看你附近的晚霞评分。`
- 照片说明要写边界：`上传后可能展示在公开分享地图，你可以之后申请删除。`

## 8. iOS 复用口径

未来 iOS 复用以下内容：
- 颜色、圆角、层级、字号区间的 token 语义。
- 信息优先级：分数、窗口、指标、解释、操作。
- API 字段语义、错误码、人类可读文案方向。
- 分享、上传、地图聚合的数据结构。

未来 iOS 不复用：
- WXSS 变量名、WXML 结构、小程序组件私有样式。
- 微信授权 API、`wx.chooseMedia`、`wx.uploadFile` 的平台代码。
- 微信分享卡片实现；只复用分享参数和落地解析语义。

## 9. 落地检查

每个小程序样式 PR 至少自查：
- 分数、窗口、关键指标在窄屏首屏可读。
- 卡片默认圆角符合 `8px` 语义。
- 主按钮只有一个，且暖橙只用于主要行动。
- 拒绝定位、上传失败、空收藏、弱网均有恢复路径。
- 照片上传前明确公开展示风险。
- 新增 token 或组件语义能映射到未来 iOS，不依赖 WXSS 私有实现。
